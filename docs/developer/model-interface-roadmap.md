# Model interface requirements and capability audit

This audit distinguishes three questions: (i) whether QVR can state a model;
(ii) whether an execution path can fit it; and (iii) whether the Python interface
provides the corresponding data preparation and analysis workflow. Expressibility
alone does not establish parity with another modeling system.

The implementation supplies checked input schemas, explicit runtime parameters,
finite extent inference, reusable inference methods, new-data prediction, and raw
pointwise observation likelihoods. The tables below record
remaining work against brms and the open enhancement issues as of November 16, 2026.

## brms coverage

The released comparison baseline is
[brms 2.23.0 on CRAN](https://CRAN.R-project.org/package=brms), published
September 9, 2025, with its
[source metadata pinned at `b124949c`](https://github.com/cran/brms/blob/b124949c14067aa658b176d26477ccf715881bf9/DESCRIPTION).
The audit also checks the official development snapshot
[`f4f906dc`, dated November 12, 2026](https://github.com/paul-buerkner/brms/commit/f4f906dc0db56fd42b58cdd7d57e76b40f650331),
whose [metadata identifies version 2.23.2](https://github.com/paul-buerkner/brms/blob/f4f906dc0db56fd42b58cdd7d57e76b40f650331/DESCRIPTION).
That development version is distinct from the CRAN release. The website's
[reference index](https://paulbuerkner.com/brms/reference/index.html),
[formula specification](https://paulbuerkner.com/brms/reference/brmsformula.html),
[family catalog](https://paulbuerkner.com/brms/reference/brmsfamily.html), and
[fitting interface](https://paulbuerkner.com/brms/reference/brm.html)
describe the development version.
These sources establish the comparison's scope; the QVR assessments below come
from the implementation and its tests. Full brms coverage is not established.

| Capability | QVR evidence and remaining requirements |
| --- | --- |
| Data dimensions and external inputs | `Model.schema` retains checked types and roles; `Model.bind` specializes finite extents and validates supplied values. Tested in `tests/modeling/test_model.py`. |
| Common regression families | `quivers.formulas.families` contains 50 entries, with 17 inverse links and mean/precision conversions for binomial, beta-binomial, gamma, Weibull, and other families. Asymmetric Laplace quantile regression supports a fixed or regressed quantile, with independent SciPy density/CDF/quantile and sampling tests. `tests/test_formula_distributional.py` checks independent likelihood and derivative oracles. ExGaussian uses the response mean and Gaussian/exponential components; inverse Gaussian uses response mean/shape with implicit sample gradients. These have independent density, CDF, derivative, and sampling oracles. Zero-inflated Beta regression reuses the native zero/one mixture with its one-atom probability fixed at zero; atom/interior densities, endpoint derivatives, sampling moments, and response means have independent oracles. Hurdle Gamma and LogNormal responses use a shared exact atom/positive-component implementation, with independent density, derivative, CDF, moment, and sampling oracles and SVI/HMC/NUTS formula checks. All 49 named laws in the pinned brms 2.23.0 family-function registry map to formula frontends; its remaining function is the custom-family constructor. The larger native registry remains a separate interface. Named-law coverage does not establish every link, modifier, interaction, prior, or custom-law workflow. |
| Zero-inflated and hurdle counts | Native and formula interfaces add zero-inflated negative-binomial, binomial, and beta-binomial responses plus hurdle negative-binomial responses. `tests/test_formula_count_mixtures.py` checks component-to-regression conversions, likelihood and gradient oracles, fitting, and predictions. Shared `Family.trials_parameter` metadata validates trial counts in `0..2**53` at fitting and new-data prediction; zero trials give a zero response. Native Binomial/BetaBinomial/NB/Poisson and the new mixtures use float64 count parameters, scores, and moments while preserving gradients to original learned heads. The hurdle sampler uses compound-Poisson/logarithmic-count sampling rather than rejection from a vanishing positive event. Native/QIEC reference execution supports all four; all 11 external renderers explicitly refuse them, checked in 44 family/backend cells. Poisson and negative-binomial hurdles use `hu` for the entire zero probability, while zero-inflated families retain `zi` for structural-zero mass. |
| Finite mixtures | `mixture(...)` builds the brms mixture of any real-support or any integer-support families, with `nmix`, `order` (`"mu"`/`"none"`/bool, brms's default), component formulas (`mu2 ~ z`, `sigma1 ~ x`), a Dirichlet `theta` simplex, proportions predicted for all but one component through a row-wise softmax, fixed proportions, and equated parameters (`equal={"sigma2": "sigma1"}`). Each component is the ordinary single-family emission renamed into its `dpar_<name><k>_` namespace, so every predictor term, prior, link and `cens`/`trunc` check applies per component. Gaussian mixtures use the native `MixtureNormal` kernel and others the general `Mixture`. Ordering is an exact positive-gap reparameterization of the sampled intercepts (centered under `default_priors="brms"`, as in brms). Truncation normalizes each component on its interval, as brms does. `pp_mixture`, `posterior_linpred(parameter="mu")` (all component locations), `posterior_epred`, `posterior_predict` and `log_likelihood` follow brms; SVI, HMC, NUTS, new rows, refits, k-fold, artifacts and joint models are tested in `tests/formulas/test_mixture.py` against hand-written torch densities (values, gradients, Hessians), SciPy component laws and brms 2.20.4 `log_lik`, `pp_mixture` and `posterior_epred` at brms's draws. Different by design: under ordering the later intercepts have no prior of their own, and the gaps carry `HalfNormal(5)` (class `mixture_intercept_spacing`). Group identifiers shared by component formulas form one correlated block across components, as in brms. A parameter equated to a sampled one is reported in `draws()` and `variables()` under its own name, as brms's transformed parameter is (`tests/formulas/test_prior_table_options.py`, pinned by `tests/formulas/oracles/brms_prior_table_options.R`). Mixtures of ordinal families (`cumulative`, `sratio`, `cratio`, `acat`, `hurdle_cumulative`; never with other families) compose the ordinary ordinal emission per component, with per-component thresholds, `disc<k>` formulas and `cs()` terms under `order="none"` (brms's default for ordinal mixtures) and one shared threshold vector under `order="mu"`, ordered when any component is cumulative, as in brms. `posterior_epred` returns mixed category probabilities, and `posterior_predict`, `pp_mixture`, `log_likelihood`, LOO, k-fold, `bayes_r2`, conditional effects, refits and artifacts use the shared paths. `tests/formulas/test_ordinal_mixture.py` checks torch category laws written from the model definitions (values, gradients, Hessians) and brms `log_lik`, `posterior_epred` and `pp_mixture` at brms's draws for separate and shared thresholds (`oracles/brms_ordinal_mixture.R`). Different by design: each ordinal component keeps the quivers threshold coordinates (location intercept and centered thresholds) and their default priors. Ordinal mixtures accept `thres(n, gr)`: every component has its own unpooled vector per group, and `order="mu"` shares one vector per group across the components by reading one component's group-by-threshold matrix and intercept. brms compiles this model but its `log_lik` and `posterior_epred` fail on it (pinned), so `tests/formulas/test_threshold_group_models.py` checks the density with first and second derivatives against the mixture of group-specific category laws written from brms's Stan statements, scores at brms's draws, SVI, HMC, NUTS, new rows, refits, k-fold and artifacts. Deliberately different from brms: the group thresholds of a mixture keep their native coordinate names, and a mixture with threshold groups whose components mix hurdle and other ordinal families is refused. Not available: shared thresholds with equidistant thresholds (refused by brms too) or hurdle components, and custom, Wiener and Cox components. |
| Category-specific predictors | Categorical, multinomial, Dirichlet, Dirichlet-multinomial and logistic-normal responses accept brms `mu<c> ~ ...` formulas for non-reference categories (`muB`, `muC`, with `with_reference` for `refcat`). The main formula predicts the other categories; each category has its own coefficients, group effects and `dpar="muC"` priors, and `posterior_linpred(parameter="muC")` reads one category. Identical formulas reproduce the shared emission exactly. `tests/formulas/test_category_formulas.py` checks torch softmax densities with derivatives, SciPy multinomial and Dirichlet laws, brms names and `log_lik`/`posterior_epred` at brms draws, inference, new rows, artifacts and joint models. Per-category predictors are ordinary scalar predictors, so `mo()`, `gp()` (approximate and exact), `mm()` and the `gr()` options `by`, `dist` and `pw` give each free category its own simplex, hyperparameters and group standard deviations, and a main formula holding one of them is copied to every free category, as in brms. `tests/formulas/test_category_special_terms.py` checks brms variable names, prior rows and `log_lik`/`posterior_epred` at brms's draws (`oracles/brms_category_special_terms.R`), NumPy predictors with SciPy multinomial, Dirichlet and Dirichlet-multinomial laws, SVI, HMC, NUTS, new rows, refits, k-fold and artifacts. `logistic_normal` accepts brms `sigma<c> ~ ...` formulas for the scale of each non-reference component's log ratio (`sigmab ~ x`): a predicted scale is a scalar predictor under the log link with `dpar="sigmab"` priors and brms names (`b_sigmab_x`), a scale without a formula is the scalar class `sigmac`, and `fixed_parameters` holds one constant. `tests/formulas/test_logistic_normal_scales.py` checks brms's Stan statements, prior rows and messages, `log_lik` and `posterior_linpred` (location and scale, training and new rows) and variable names at brms's draws (`oracles/brms_logistic_normal_scales.R`), the density with first and second derivatives against a torch multivariate Normal with the Jacobian and SciPy, SVI, HMC, NUTS, new rows, refits, k-fold, artifacts, typed priors, joint models and refusals. Deliberately different from brms: `sigma ~ ...`, which brms refuses, predicts every scale with one formula and one coefficient per component, and it cannot be combined with `sigma<c>`. Not available: `me()` in a distributional formula (located error); `mo()`, `mm()` and `gr()` options in the shared logistic-normal `sigma` formula, which keeps one coefficient per category. |
| Group effects | Single-bar blocks use native LKJ Cholesky correlations; double bars request independence. Shared IDs couple coefficients across location and auxiliary formulas. Scalar and component blocks support centered and noncentered coordinates, including all non-reference-category coefficients. `tests/test_formula_correlations.py` checks Gaussian covariance densities, derivatives, and SVI/HMC/NUTS execution. Mixed scalar/transition widths and shared auxiliary blocks retain their joint covariance in both coordinate systems, checked against native/reference densities and every parameter gradient. New-group prediction supports joint donor and fitted Gaussian/LKJ policies. `GroupCovariance` supplies labeled SPD covariance or explicitly ranked PSD support through the same Gaussian layout and MatrixNormal law, including grouped cutpoint profiles and Schur-conditional new-level prediction. brms grouping syntax is normalized onto the same layout (`tests/formulas/test_grouping_syntax.py`, oracle `tests/formulas/oracles/brms_grouping.R`): `gr(g, cor, id, cov)` (`cov` reads a labeled `data2` matrix into `GroupCovariance`, retained by the fit), interactions `g1:g2` with brms's `_`-pasted levels, and nesting `g1/g2` as `g1` plus `g1:g2`. Independent coefficients (`||`, `cor = FALSE`) of a factor with a known level covariance follow that covariance, each in its own block. A coefficient repeated across blocks of one factor is refused, as brms refuses it. Multi-membership `mm(g1, ..., gK, weights, scale, cor, id)` and `mmc()` codes the union of member levels through `IndexedDesign` and replaces each row gather by a weighted sum over members, O(n K) per coefficient, reusing the Gaussian group layout, LKJ blocks, priors (group label `mm<members>`), and new-level policies on one compact prediction axis (`tests/formulas/test_membership.py`, oracle `tests/formulas/oracles/brms_membership.R`, pinned `J`, `W`, `Z`, and generated Stan predictors). `gr(by = )` gives each `by` level its own standard deviations and LKJ factor (brms `scale_r_cor_by`), `gr(dist = 'student')` adds brms's `df ~ gamma(2, 0.1)` (lower bound one), per-level `udf ~ inv_chi_square(df)`, and `dfm = sqrt(df * udf)` multipliers, and `gr(pw = )` weights each level's standard-normal innovation prior (pinned from the brms 2.23 source, absent from 2.20.4). `tests/formulas/test_group_options.py` pins brms 2.20.4 `Jby`, `Nby`, priors, and generated Stan effect statements (oracle `tests/formulas/oracles/brms_group_options.R`) and checks the Student-t density with every first and second derivative. Not supported, refused with a located error: these three options with centered coordinates or a known level covariance; `by` and `pw` on `mm()` factors (brms takes matrices); mixing options across blocks of one factor; and `mm()` with category-specific coefficients, which brms admits, or grouped thresholds. `mm(..., cov = K)` composes the membership gather with the known-covariance block of `gr(cov = )`, checked against a torch density written from brms's `Lcov`, `J`, `W` and `Z` with first and second derivatives and against brms `posterior_linpred` and `log_lik` at its draws on training and fresh rows (`tests/formulas/oracles/brms_membership_covariance.R`, `tests/formulas/test_membership_covariance.py`). Deliberately different: correlated coefficients of a factor with a known covariance have the exact Kronecker covariance, where brms's `scale_r_cor_cov` skips the entries of `Lcov` that are not above `1e-10` and so departs from it when the Cholesky factor has a negative entry. The three options and `mm()` in the per-category predictors of categorical and compositional responses are described in the category-specific predictors row. |
| Distributional and nonlinear formulas | Additive formula leaves and `NonlinearExpression` nodes share one checked `PredictorGraph`. Location, auxiliary, and nonlinear parameters use its dependency ordering, QVR expression typing, and retained input/design metadata. Component expressions retain named category coordinates, including reference exclusions. `tests/test_formula_nonlinear.py` checks independent joint densities, every fitted head gradient, native/reference agreement, SVI/HMC/NUTS, and compilation-free new-data replay. Joint multivariate responses compose these graphs per response (see Multivariate responses). Deliberately different: parameter formulas are arguments of `bf` or the `distributional` and `nonlinear` keywords, and brms's `lf`, `nlf`, `acformula`, and `set_nl` are not provided. |
| Multivariate responses | `bf`, `mvbf`, `set_rescor`, and `bf(...) + bf(...)` build a `MultivariateFormula` with brms response names; `fit`, `get_prior`, `formula_to_qvr`, and `sample_prior` accept it and return a `MultivariateFit`. One joint program namespaces every single-response emission, couples shared group identifiers in one LKJ block, and applies one prior catalogue with `response` selectors. `set_rescor(True)` joins scalar Gaussian or Student responses under a multivariate Normal or Student row event with brms's `diag(sigma) Lrescor` factor and one shared `nu`; the brms default (rescor exactly for one common Gaussian/Student family without `mi()`) applies when unset. Heterogeneous families are allowed without residual correlation, and every one of the 50 registered families fits, predicts, and scores as a response beside a Gaussian response with a shared group block (`tests/formulas/test_multivariate_public.py`). `posterior_linpred`, `posterior_epred`, `posterior_predict`, and `log_likelihood` take `resp` and `new_data`, reuse each response's ordinary row preparation, and draw a new level of a shared factor once per block. Pointwise units follow brms `log_lik`: the row event under rescor (exact marginal for a response subset) and per-row sums otherwise. `variables` and `hypothesis` use brms names (`b_<resp>_<coef>`, `sd_<group>__<resp>_<coef>`, `cor_...`, `rescor__<a>__<b>`), pinned against brms output in `tests/formulas/oracles/brms_multivariate.R`. `update`, `refit_callback` (k-fold and exact LOO), and `save_fit`/`load_fit` reuse the shared recipe, runner, and artifact storage. Independent SciPy multivariate Normal/Student and hand-written heterogeneous joint-density oracles check values and every first derivative. A cumulative response with category-specific effects predicts on fresh rows inside a joint model, and `mi()` responses fit and predict there (the "Missing data and measurement error" row gives their limits). `MultivariateFit.bayes_r2` returns brms's `bayes_R2` per response. `mi()` responses fit under residual correlation as in brms, the joint law scoring each row's completed vector. Not supported: neural predictors and joint refit partitions with `subset()` rows. |
| Splines, Gaussian processes, and special predictor terms | Some corresponding kernels exist. Ordinal `cs(expr)` effects retain a transition axis with centered or noncentered shared correlations. Cumulative/hurdle effects use training-domain bounds and proper conditional slack priors to ensure ordered effective cutpoints. Flexible, sum-to-zero, and equidistant grouped threshold profiles share an identified location/shape construction; binary profiles retain only their location degree of freedom. Prediction retains fitted cutpoints, exposes `posterior_thresholds`, and reuses support-conditioned new-group policies. brms `thres(n, gr)` gives each level of `gr` its own unpooled threshold vector of its own length (count from `n`, a number or a column constant within a group, or from the group's largest response), for the cumulative, `sratio`, `cratio`, and `acat` families: every group keeps the identified location and centered shape coordinates (the first group's location is zero under a formula intercept), shorter vectors are padded with finite thresholds, and the padded category log masses are reduced exactly to the group's own categories (log-sum-exp of the padded tail for cumulative and sequential laws, removal before normalization for adjacent-category laws), so absent categories have probability zero. `variables()` reports brms's `b_Intercept[<group>,<k>]`, fresh rows are coded against the fitted groups, and counts, Stan statements, names, `log_lik`, and `posterior_epred` are pinned against brms at its draws (`tests/formulas/oracles/brms_threshold_groups.R`, `tests/formulas/test_threshold_groups.py`), with values and first and second derivatives checked against per-group category laws written from brms's Stan functions. Different by design: the threshold coordinates and their default priors are quivers's, as for a single threshold vector. `hurdle_cumulative` takes threshold groups with code zero as the hurdle outside every group's thresholds, and `thres(n)` counts the thresholds above the hurdle, as brms does. A multivariate model reports `b_<resp>_Intercept[<group>,<k>]`, and `b_<resp>_Intercept[<k>]` for a cumulative response with one vector, from one replay of the row thresholds through the shared variable catalogue, in `variables()` and `summary()`. `tests/formulas/test_threshold_group_models.py` pins brms's counts, Stan statements, names, `log_lik` and `posterior_epred` at its draws for the hurdle and the multivariate model (`oracles/brms_threshold_group_models.R`). Refused with a located error: category-specific effects (brms's message), equidistant or sum-to-zero thresholds, `thresholds_by` beside `thres(gr)`, and a fresh row of a group without fitted thresholds. `tests/test_formula_centered_groups.py` and `tests/test_formula_group_threshold_policies.py` check coordinate densities, gradients, and predictions. `s()` and `t2()` port brms's mgcv construction (`smoothCon` with absorbed constraint and diagonal penalty, then `smooth2random`): default thin-plate regression splines (including mgcv's Lanczos iteration) and `tp`, `ts`, `cr`, `cs`, `cc`, `ps`, `bs`, `re` bases, mgcv's Gaussian process smooth `bs = 'gp'` with every covariance choice of `m` (spherical, power exponential, Matérn 1.5, 2.5 and 3.5, range, power, stationary form; equal to brms's Stan data in `tests/formulas/test_mgcv_gp_smooths.py`), the factor-smooth interaction `s(x, g, bs = 'fs')` (thin-plate base or the `cr`, `cc`, `ps`, `bs`, `gp` base named by `xt = list(bs = ...)`, equal to brms's Stan data up to the same free rotation in `tests/formulas/test_mgcv_factor_smooth_bases.py`; numeric and factor `by` applied as mgcv's own design applies it, where brms's Stan data ignore the `by` of an `fs` smooth; `fx = TRUE` and the `ts`/`cs` bases refused because brms and mgcv fail on them; one smoothing scale for the range space and one per null-space polynomial, new factor levels refused as in brms; its null-space columns are orthonormal polynomials where mgcv's are fixed only up to a rounding-dependent rotation, checked in `tests/formulas/test_mgcv_factor_smooths.py` by block structure, one common rotation and scale, fresh rows, and `posterior_linpred` at brms's draws), multivariate `s(x, z)`, numeric and factor `by`, `fx`, and `t2` tensor products with `k`, `bs`, `m`, `d`, `full`, `ord`; `te()`/`ti()` raise brms's error naming `t2`. The Markov random field `s(region, bs = 'mrf', xt = list(penalty = P))` or `xt = list(nb = A)` reads its penalty or neighbourhood matrix from `data2` (brms reads R's global environment), with low-rank `k`, `by`, `fx`, and regions without observations under `drop_unused_levels=False`; its span and implied covariance equal brms's Stan data in `tests/formulas/test_mgcv_mrf_smooths.py`, a `k` that cuts a repeated penalty eigenvalue is refused, and boundary polygons (`polys`) are not read. The spline on the sphere `s(lat, lon, bs = 'sos')` ports mgcv's kernel (`makeR` and the compiled dilogarithm series of the second-order spline, the four closed-form pseudospline orders of Wahba (1981), and the two embedded-sphere kernels of negative `m`), mgcv's rounding and clamping of `m`, the knots in the text order of `uniquecombs`, the Lanczos truncation to `k`, the null-space constraint, and the column scaling, with user `knots` for both covariates, `by`, and `fx`; kernel values, the raw constructor output, and brms's Stan data on training and fresh rows are pinned in `tests/formulas/test_mgcv_sos_smooths.py` (generator `tests/formulas/oracles/mgcv_sos_smooths.R`), with the kernels also checked against the dilogarithm, Wahba's Legendre series and integral, and the chord length. Different by design for `sos`: a latitude outside [-90, 90] or longitude outside [-180, 360] is refused (mgcv evaluates any numbers), knots for one covariate alone and more knots than rows are refused (mgcv ignores them), `xt` (`max.knots`, `seed`) and more than 2000 unique locations without knots are refused (mgcv subsamples with R's generator), and `m = -1` knots on one circle are refused. The Duchon spline `s(x, z, bs = 'ds', m = c(m, s))` ports mgcv's constructor (the kernel `DuchonE` with its sign, the polynomial null space, the knots in the text order of `uniquecombs`, the Lanczos truncation to `k`, and the Householder null space of the constraint), with user `knots`, `by`, `fx`, and use as a `t2()` margin; brms's Stan data on training and fresh rows are pinned in `tests/formulas/test_mgcv_duchon_knots.py` (generator `tests/formulas/oracles/mgcv_duchon_knots.R`), with the kernels checked against closed forms, the seminorm property, and the thin-plate span at `s = 0`. Different by design for `ds`: an `m[2]` violating Duchon's conditions is refused with a valid value named (mgcv replaces it and warns), `xt` (`max.knots`, `seed`) and more than 2000 unique rows without knots are refused. `bs = 'ad'` and `bs = 'so'` are refused by brms itself (`smooth2random` cannot convert them) and here. Unpenalized columns are class `b` coefficients and each penalized block a scaled standard-Normal block with a typed `sds` prior; fresh rows use the retained basis. `tests/formulas/test_mgcv_smooths.py` pins brms 2.20.4/mgcv 1.8-42 `Xs`/`Zs` and fresh-row matrices (generator `tests/formulas/oracles/mgcv_smooths.R`); `tests/formulas/test_mgcv_smooth_workflow.py` and `tests/formulas/test_penalized_smooth.py` check joint densities with every derivative, SVI/HMC/NUTS, prediction, `update`, k-fold, artifacts, and `conditional_smooths`. Deliberate differences: the `sds` default is the shared `random_scale_prior` (HalfNormal(1.0)) rather than brms's data-scaled half Student-t, keeping `sd` and `sds` on one response-independent default; `id` shares smoothing scales (brms ignores it); `t2` fresh rows use the training constraint (brms's prediction constraint does not reproduce its own training rows); thin-plate terms above 2000 unique covariate rows without user knots are refused (mgcv subsamples with R's generator); where mgcv's null-space basis depends on LAPACK rounding QVR fixes it canonically. Monotonic `mo()` follows brms and Bürkner and Charpentier (2020): integer predictors coded from the training minimum and ordered factors by their observed levels, a `simo` Dirichlet simplex per factor (`Dirichlet(1)` default, scalar concentrations recycled), a class `b` coefficient, interactions with numeric and factor columns and other `mo()` factors (one term, coefficient, and simplex per covariate column, as brms's `Csp`), shared `id` simplexes, `(mo(x) | g)` slopes reusing the population simplex, distributional parameters, and refusal of out-of-range, fractional, or unseen fresh values. `tests/formulas/test_monotonic.py` pins brms 2.20.4 `Xmo`, `Jmo`, `Csp`, labels, and generated Stan predictors (generator `tests/formulas/oracles/brms_monotonic.R`) and checks the joint density with every first and second derivative, SVI/HMC/NUTS, prediction, new levels, `update`, k-fold, and artifacts. Under `default_priors="brms"` the `mo()` coefficient takes brms's flat prior (class `b`); deliberate `mo()` differences under the quivers policy: the `bsp` default is the autoscaled `fixed_prior` rather than brms's flat prior. Class `b` selectors use the authored label `mo(x)` rather than brms's `mox`. A group-level `mo()` slope without its population term is refused, where brms silently drops it. A single-category predictor is refused, where brms emits an invalid zero-length simplex. `mo()` in the per-category predictors of categorical and compositional responses is described in the category-specific predictors row. Approximate Gaussian processes `gp(..., k = m)` follow brms and Riutort-Mayol et al. (2023): every brms argument (`by` numeric and factor with `cmc`, `k`, `c`, `cov` = `exp_quad`, `matern32`, `matern52`, `exponential`/`matern12`, `iso`, `gr`, `scale`), the eigenfunction basis as one Gaussian design block whose coordinate scales are `exp(log(spd)/2)` of sampled `sdgp` and `lscale`, brms's default priors (half Student-t `sdgp` scaled by the response's link-scale MAD, inverse-gamma `lscale` solved from the training distances), brms's `coef` labels, retained scaling, centering, and boundary for fresh rows, and `conditional_smooths` for one GP term. `tests/formulas/test_gp.py` pins brms 2.20.4 `Xgp`, `slambda`, `Jgp`, `Igp`, `Cgp`, and default priors (generator `tests/formulas/oracles/gp_brms.R`), checks spectral densities against kernel Fourier transforms, the published accuracy relations of the approximation, the joint density with every first and second derivative, SVI/HMC/NUTS, fresh rows, `update`, k-fold, and artifacts. Exact Gaussian processes `gp(...)` without `k` (or `k = NA`) follow brms's non-centered `cholesky(K(sdgp, lscale) + 1e-12 I) zgp` over the distinct inputs (`gr`), with the same arguments, kernels (non-iso as a product of one-dimensional kernels), labels, and default priors as the approximation, through the checked QVR builtin `cholesky`. New inputs are drawn from brms's conditional Gaussian given the replayed training values with its `1e-8` nugget (`.predictor_gp_new`), as a fresh prediction site, and `conditional_smooths` draws the same law. There is no size limit, as in brms. `tests/formulas/test_gp_exact.py` pins brms 2.20.4 exact `Xgp`, `Jgp`, `Nsubgp`, `Igp`, `Cgp`, priors, and Stan construction, and checks the joint density with every first and second derivative for all four kernels against a hand-written oracle, the prior covariance of the latent function by Monte Carlo, the conditional law against its closed form, agreement with the approximation within the published accuracy, SVI/HMC/NUTS, new-input prediction against the per-draw conditional law, `update`, k-fold, and artifacts. `tests/dsl/test_cholesky_builtin.py` checks the builtin. Deliberate differences: predictions add every `by` sub-GP as brms's Stan model does (brms's R `predictor_gp` assigns them), and brms's prediction `nug` argument is not exposed. `gp()` in per-category predictors is described in the category-specific predictors row. Full coverage requires an executable fixture for every supported feature and
interaction, an independent density or prediction oracle, and a stated tolerance.
For instance, comparing correlated effects requires checking the covariance
model; matching a formula's printed text would not establish the same prior.

The pinned [released family registry](https://github.com/cran/brms/blob/b124949c14067aa658b176d26477ccf715881bf9/R/family-lists.R)
and [development family registry](https://github.com/paul-buerkner/brms/blob/f4f906dc0db56fd42b58cdd7d57e76b40f650331/R/family-lists.R)
each contain 49 named entries plus `custom`; their definitions agree apart
from trailing whitespace. QVR's 50 formula entries cover all 49 of those names
after normalizing `student`/`student_t`, `negbinomial`/`negative_binomial`,
and `inverse.gaussian`/`inverse_gaussian`. Its remaining entry is generic
mixture composition. This name comparison does not establish equivalent
parameterizations, links, or fitting behavior.

Deliberate differences in the family registry: `Gamma` and `Beta` are
`gamma` and `beta`, and the negative binomial shape is the parameter `disp`
(brms `shape`). `inverse_gaussian` defaults to the log link (brms `1/mu^2`,
available as `inverse_square`), which keeps the mean positive for every
linear predictor. `student_t` leaves `nu` unbounded below under the quivers
prior policy (brms bounds it at one, as `default_priors="brms"` does), and
`posterior_epred` raises for draws with `nu <= 1`. brms's `d`/`p`/`q`/`r`
functions have no counterpart: the native laws are distribution objects
with `log_prob`, `cdf`, `icdf`, and `sample` methods, and the Student-t,
von Mises, and zero-inflated beta laws have no public `cdf` or `icdf`.

The `cox` and `xbeta` formula frontends complete this name inventory.
`cox` retains an identified normalized spline baseline and a proper
positive-hazard tail through the generic `BernsteinHazard` law; `xbeta`
reuses an affine Beta law and censoring atoms. Neither name establishes
all baseline-group, response-modifier, prior, or workflow behavior.
The native kernel registry is a separate capability: a native distribution
does not imply its corresponding formula workflow. `dirichlet2` is an
alternate parameterization, rather than a new distribution law.

The vector frontends share the categorical compiler's component
coordinates and the ordinary posterior replay machinery. Multinomial
and Dirichlet-multinomial responses retain integer row totals;
Dirichlet responses retain mean/precision or component-concentration
parameterizations. Additive-log-ratio Normal responses retain an
explicit reference component, covariance coordinates, and the simplex
Jacobian. Their optional Monte Carlo response expectations require an
explicit sample budget. Independent tests compare complete joints,
every fitted coefficient gradient, mixed-width group correlations, and
new-data predictions. Joint multivariate formulas and residual
correlations are described in the multivariate responses row.

Wiener formulas retain unsigned reaction times and decisions as separate
typed inputs and encode their joint law inside QVR. The native and
reference kernels share one certified rejection sampler. Density and
moment tests use independent series and differential-equation oracles;
formula tests cover SVI, HMC, NUTS, all distributional-parameter
derivatives, and new-data predictions. Low-level predictive draws retain
the signed joint encoding, while structured response draws decode
reaction time and decision without repeating sampling. This does not
establish support for every response modifier.

COM-Poisson and all five ordinal constructions now have formula
frontends. COM uses the pinned compiled rate law consistently for fitting
and prediction, while the released R helpers use a mode parameterization.
The [COM guide](../guides/analysis-data-and-formulas.md#com-poisson-rate-and-response-mean)
states this discrepancy and the resource limits. The
[ordinal guide](../guides/analysis-data-and-formulas.md#ordinal-families-thresholds-and-category-specific-effects)
states all 28 family/link combinations, discrimination checks, threshold
support, and differences between QVR's identified-coordinate priors and
the pinned brms defaults. These implementations do not establish full
prior, response-modifier, or workflow parity.

The released registry also includes `squareplus` and `softit` links,
which the website's abbreviated link lists do not enumerate. QVR now
implements both with stable staged expressions; value and first/second
derivative tests include the origin and large finite predictors. Neither
the family count nor QVR's 17 inverse links establishes full coverage.
Links, thresholds, response modifiers, interactions, and the other
workflows in the table need separate acceptance tests against each pinned
baseline. Future audits should compare released and development sources
independently, retaining their commit identities and support status.

Skew-normal, shifted-lognormal, Fréchet, and GEV frontends distinguish
native location/scale parameters from response means, retain support and
moment domains in prediction, and state their GEV shape-prior policy.
`tests/test_formula_shape_families.py` checks those conversions, priors,
and predictions; `tests/continuous/test_shape_families.py` checks the
native numerical, derivative, and sampling contracts. All four support
native and checked-reference execution; all 11 external targets refuse
them explicitly. The native `Truncated` wrapper now uses deterministic
interval masses for independent scalar coordinates, while coupled events
without a joint rectangle-mass operation remain refused. Formula response
truncation and censoring use the same endpoint-aware event operation. Their
scalar-response contract does not imply a joint rectangle capability for coupled
vector events.

Discrete Weibull and zero-inflated asymmetric Laplace now have native
and checked-reference kernels, with independent source-density and
formula-prediction checks. Their 22 family/backend cells all refuse
external rendering explicitly. The formula-only `negbinomial2` frontend
adds reciprocal dispersion to the existing negative-binomial law, with
a direct `Gamma(0.4, 0.3)` prior on `sigma`. Formula density, coefficient
gradient, SVI/HMC/NUTS, and new-data prediction checks are in
`tests/test_formula_reparameterized_families.py`. Discrete Weibull
expected responses retain explicit tail-certification and work limits;
its main transformed predictor is a probability rather than a mean.
