# Encoders

An [encoder](../../guides/structural-compression-signatures-and-encoders.md#encoder-blocks) folds a
term into a vector by combining its children's vectors into a vector for their parent. `Encoder` is
a `torch.nn.Module` that implements this fold, the
[catamorphism](https://en.wikipedia.org/wiki/Catamorphism) $T_\Sigma \to \mathrm{Vec}_D$ out of the
[initial algebra](https://ncatlab.org/nlab/show/initial+algebra+of+an+endofunctor) of terms over a
signature [@lambek1968fixpoint], as in recursive and tree-structured neural encoders
[@tai2015treelstm]. The framework gives the recursion, and the function for each operation is either
given by the analyst or generated by the compiler as a two-layer MLP whose input dimensions follow
the operation's arguments. The learned functions determine which distinctions of the
[input](../../tutorials/qvr/12-structural-autoencoders.md#2-construct-typed-host-data) the vector
keeps.

For binders, the framework threads a typed context Γ of
[de Bruijn indices](https://en.wikipedia.org/wiki/De_Bruijn_index) through
the recursion. It compresses each binder's annotations in the outer
context, creates variable embeddings with `var_init_fns`, and recurses
over the scoped arguments in the extended context.

`forward_graph` encodes graph signatures as a message-passing network
[@battaglia2018relational]. It applies an initial embedder for each vertex kind, a fixed number of
rounds of message passing with functions indexed by edge and vertex kind, and a readout that
reduces the final vertex embeddings to one vector for the graph.
